## chunker.py — SlidingWindowChunker

Splits `plain.txt` into overlapping chunks suitable for BM25S and KeyBERT input.

### Class: `SlidingWindowChunker`

**Parameters:**
- `chunk_size: int = 200` — target word count per chunk. A new chunk begins once this is reached. A sentence that would push the count over this limit is NOT added to the current chunk (it starts the next), unless the chunk is still empty (avoids infinite loops on very long sentences).
- `overlap: int = 50` — word count shared between consecutive chunks. After each chunk is emitted, the chunker steps back through the trailing sentences of that chunk until it has covered at least `overlap` words, and restarts the next chunk from that sentence. Never splits mid-sentence.

**Method: `chunk(plain_text, blocks) -> list[dict]`**

Returns a list of chunk dicts with:
- `chunkId` — `"chunk-000001"` format, 1-indexed, 6 zero-padded
- `index` — zero-based position
- `text` — chunk text (sentences joined by space)
- `wordCount` — actual word count of this chunk
- `sourceBlockIds` — list of `blockId` strings from blocks whose `text` field contains one or more sentences via substring match

**Sentence splitting:**
1. spaCy `blank("en")` + `sentencizer` pipeline (preferred)
2. Fallback: split on `". "`, re-attaching the period to each non-final segment

**Graceful failure:** every method is wrapped in `try/except`. Any exception in `chunk()` returns `[]` and logs a warning. The spaCy model is loaded lazily and cached. If spaCy is not installed, a warning is printed at import time and the fallback is used silently thereafter.

## labeller.py — NLULabeller

Ensemble labeller combining BM25S retrieval scores, KeyBERT semantic keyphrase extraction, and spaCy interrogative pattern detection.

### Class: `NLULabeller`

**Parameters (all overridable by environment variable):**

| Parameter | Default | Env var |
|---|---|---|
| `keybert_model` | `"all-MiniLM-L6-v2"` | `KEYBERT_MODEL` |
| `bm25s_top_n` | `20` | `BM25S_TOP_N` |
| `keybert_top_n` | `20` | `KEYBERT_TOP_N` |
| `keybert_threshold` | `0.55` | `KEYBERT_THRESHOLD` |
| `agreement_confidence` | `0.91` | `AGREEMENT_CONFIDENCE` |
| `fallback_confidence` | `0.72` | `FALLBACK_CONFIDENCE` |
| `question_confidence` | `0.60` | `QUESTION_CONFIDENCE` |

If an env var is set to a non-parseable value, the constructor default is used silently.

**Method: `label(chunks, blocks) -> list[dict]`**

Returns a deduplicated, confidence-sorted list of candidate dicts matching the `ExtractedCandidate` shape:

```python
{
    "candidateType":     "vocab" | "expression" | "question" | "unknown",
    "text":              str,           # original extracted text
    "normalizedText":    str,           # lowercased and stripped
    "sourceBlockId":     str | None,    # blockId where candidate was found
    "sourcePageNumber":  int | None,    # from block source if available
    "sourceSlideNumber": int | None,    # from block source if available
    "confidence":        float,
    "metadata":          dict,          # engine details (see below)
}
```

---

### Internal method: `_score_bm25s(chunks) -> dict[str, float]`

1. Tokenizes all chunk texts using `bm25s.tokenize(texts, stopwords="en")`
2. Builds a `bm25s.BM25` index over the tokenized corpus
3. Queries each chunk against the full corpus (each chunk's text is used as the BM25S query, retrieving top `bm25s_top_n` chunks)
4. For each retrieved document, iterates over its words and records the BM25S score of that document as the word's score (taking the maximum score seen across all queries)
5. Applies min-max scaling so all scores fall in `[0.0, 1.0]`

Returns `word -> normalised_score`. Single-word tokens only (BM25S is a bag-of-words model).

**Known limitation:** requires at least 2 chunks to produce meaningful discriminative scores. If fewer than 2 chunks are passed, a warning is logged and `{}` is returned, causing the ensemble to fall back to KeyBERT-only mode.

---

### Internal method: `_score_keybert(chunks) -> dict[str, float]`

1. Loads `KeyBERT` with the configured sentence-transformer model (lazy, cached)
2. For each chunk, calls `extract_keywords(text, keyphrase_ngram_range=(1, 3), top_n=keybert_top_n, stop_words="english")`
3. Aggregates scores per keyphrase across all chunks by taking the **maximum** score seen for that keyphrase
4. Returns `keyphrase -> max_score`

Keyphrases are lowercased before aggregation. Per-chunk failures are skipped with a warning; the method returns whatever was successfully collected.

---

### Internal method: `_detect_questions(blocks) -> list[dict]`

Iterates over blocks and sentence-splits each block's `text` using spaCy (or the `". "` fallback). For each sentence:

- **Ends with `?`** → always marked as a question candidate
- **Starts with a question word** (`What`, `Where`, `When`, `Who`, `Why`, `How`, `Which`, `Whose`, `Whom`) **AND contains a verb** (spaCy POS tag `VERB` or `AUX`) → marked as a question candidate
  - If the loaded spaCy model has a tagger/morphologizer component, POS tags are used
  - If only the `sentencizer` is available (no tagger), the verb check is skipped and the question-word match alone is accepted

Returns candidate dicts with `candidateType = "question"`, `confidence = question_confidence`, and `metadata = {"engine": "spacy_pattern"}`. `sourcePageNumber` and `sourceSlideNumber` are read from `block["source"]["pageNumber"]` and `block["source"]["slideNumber"]` when present.

## Ensemble ranking logic

```
Step 1  Run _score_bm25s(chunks)  →  bm25s_scores: dict[word, float]
Step 2  Run _score_keybert(chunks) → keybert_scores: dict[keyphrase, float]
Step 3  Build top-N sets from each dict

For every keyphrase in keybert_scores:
    token_count = len(keyphrase.split())
    if token_count == 1   → candidate_type = "vocab"
    elif token_count <= 3 → candidate_type = "expression"
    else                  → skip (too long)

    if bm25s_available AND keyphrase in bm25s_top_N AND keyphrase in keybert_top_N:
        tier = "agreement",  confidence = AGREEMENT_CONFIDENCE (default 0.91)
    elif keyphrase in keybert_top_N AND keybert_score > KEYBERT_THRESHOLD:
        tier = "fallback",   confidence = FALLBACK_CONFIDENCE  (default 0.72)
    else:
        skip (rejected)

Step 4  Run _detect_questions(blocks) → question candidates at QUESTION_CONFIDENCE (0.60)
Step 5  Deduplicate: same normalizedText → keep higher confidence
Step 6  Return combined list sorted by confidence descending
```

## Token count → candidate type mapping

| Token count | Candidate type | Typical tier |
|---|---|---|
| 1 | `vocab` | agreement or fallback |
| 2–3 | `expression` | fallback (BM25S is word-level, so agreement is rare for multi-word phrases) |
| 4+ | skipped from KeyBERT path; may appear as `question` via spaCy | — |

---

## Graceful failure rules

- If **KeyBERT model fails to load**: logs warning, `_score_keybert` returns `{}`, only question candidates (spaCy) are returned
- If **BM25S fails or returns no scores**: logs warning, `bm25s_available = False`, all qualifying KeyBERT results use `fallback_confidence` (agreement tier is never assigned)
- If **spaCy is unavailable**: question detection runs using `". "` sentence splitting and question-word-only heuristic (no POS verb check)
- `label()` catches all exceptions and returns `[]` rather than raising

---

## Known limitations

1. **No text cleaning layer yet.** Raw block text is passed directly to KeyBERT and BM25S. Noise blocks (headers, page numbers, boilerplate) degrade extraction quality. `cleaner.py` is deferred.
2. **Model load time.** First call to `label()` triggers lazy loading of the sentence-transformer model used by KeyBERT. On cold Lambda starts this may add several seconds.
3. **BM25S requires multiple chunks.** With a single chunk the index has no cross-document IDF signal. The method logs a warning and returns `{}`, causing the ensemble to fall back to KeyBERT-only mode automatically.
4. **Multi-word phrases rarely reach agreement tier.** BM25S scores individual words; a keyphrase like `"critical thinking"` will not appear in `bm25s_top_set` as an exact match. Expressions are effectively always in the fallback tier. Agreement tier is meaningful primarily for single-word vocabulary candidates.
5. **spaCy POS tagging requires a full model.** If only `spacy.blank("en")` with `sentencizer` is available (i.e., `en_core_web_sm` not installed), the verb check for question-word sentences is skipped, which may increase false positives for questions.

### blocks=[] — why and what it means

`CandidateExtractorEvent` carries only `plain_text: S3ObjectPointer` (the S3 path to `plain.txt`).
It does not carry a blocks prefix. Reading blocks from S3 would require listing the `blocks/`
prefix and fetching each object individually — a significant addition not in scope here.

Both `SlidingWindowChunker.chunk(plain_text, [])` and `NLULabeller.label(chunks, [])` handle an
empty blocks list gracefully:

- **Chunker:** `sourceBlockIds` will be `[]` for every chunk (no substring match possible). Chunking
  itself is unaffected.
- **Labeller — vocab/expression path:** `_find_source_block` returns `(None, None, None)`. Candidates
  are produced but have `sourceBlockId=None`.
- **Labeller — question path:** `_detect_questions([])` iterates over nothing and returns `[]`.
  Questions embedded inside plain_text will not be detected on this path.

Net effect: vocabulary and expression candidates are produced normally; question candidates are
absent until blocks are wired in (see "What still needs wiring" below).

---

### What happens when labeller returns empty

`NLULabeller.label` returns `[]` when:
- Both KeyBERT and BM25S fail to load or score anything, AND
- No blocks were passed (so question detection finds nothing)

In this case `handler` sets:
```python
status  = "partial"
warnings = ["NLU labeller returned no candidates"]
```

The callback is still posted with `status="partial"` and an empty `candidates` list. The Lambda
returns `{"statusCode": 200}` (not 500) because the pipeline ran successfully — it just found
nothing. A 500 is reserved for unhandled exceptions in the extraction path.
